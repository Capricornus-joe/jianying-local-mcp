# 我把一支国风短片，重建成了真正能改的剪映工程

> **59.52 秒，23 个场景，28 句字幕。画面有国风，工程有层次，后续修改有入口。**

[![《入戏·川剧初体验》成片预览](assets/showcase-poster.jpg)](assets/showcase-preview.mp4)

▶ [观看案例视频（720p 网页展示版）](assets/showcase-preview.mp4)

这个项目来自一次很具体的需求：把《入戏·川剧初体验》的视觉设计重新放回剪映时间线，并保留继续编辑的能力。

舞台、唱腔、身段、变脸、扮妆、传习——整支片子用层叠照片、书法题字、纹样、转场和旁白串起一次川剧体验。挑战在于把这些内容还原成有结构的工程，让“换一句字幕”“调整一个镜头”“修改一段运动”成为可操作的编辑动作。

## 作品背后的工程

| 维度 | 实际交付 |
|---|---|
| 成片规格 | 1920 × 1080，25 fps，59.52 秒，共1488帧 |
| 主场景 | 23个场景组合片段，按内容顺序整理 |
| 普通字幕 | 28句旁白字幕，组织为36个原生文本片段 |
| 根时间线 | 6条轨道，区分场景、字幕、音频和校正层 |
| 画面来源 | 从原始拍摄视频、照片重新建立；未把完成的动效视频塞回工程充当可编辑内容 |
| 视觉编辑 | 裁剪、缩放、位移和关键帧保留在时间线中；书法装饰使用独立图片图层 |
| 后续修改 | 普通字幕可以直接在剪映文字面板里修改，场景和音轨可以继续调整 |

为了对齐不同渲染器的取帧和首帧行为，还使用了从原始视频提取的完整帧图片，以及独立的原生姿态校正片段。它们没有烘焙完成的排版和动画；代价是部分时间线比常规粗剪更细。这是精确重建的工程选择，不代表所有剪辑都需要这么做。

## 我最看重的三件事

**作品要成立。** 国风视觉、照片层叠和书法强调服务于内容节奏，人物与字幕需要清楚、镜头与旁白需要对应。

**工程要能接手。** 字幕是能改的字，镜头有明确位置，书法和装饰有自己的图层。交给别人之后，仍能继续工作。

**结果要有证据。** 原生应用中实际打开、选择字幕、导出，再检查时序和画面。序列化成功、应用预览正常、导出结果通过，是不同层面的事实。

最终成片做了全1488帧的自动时序与画面对比，并结合场景代表帧、字幕边界和局部修正的人工目视核对。细微的字体栅格化、颜色采样和编码差异仍然存在，不能称为逐像素完全相同；自动检查也不等于人逐秒完整看完听完。

## 这与 MCP 有什么关系？

这个案例推动了 **Jianying Local MCP** 的研发：把素材、片段、字幕、样式和运动放进统一的本地编辑流程，再生成剪映工程。

v0.3 的22个工具覆盖草稿生成、普通编辑、SRT、关键帧、批量样式、本机资源引用和媒体处理。五项相关修改可以在内存中组合后只保存一次，减少中间工程、重复媒体副本和大段结果返回。

**案例同时包含针对这支作品的专项适配脚本。** 场景组合、原生字体校准、活动时间线同步及精确取帧修正尚未全部纳入通用 MCP。这个案例是实际成果展示，不是“只装插件、说一句话就能一键做出同样作品”的承诺。

现在继续推进的方向很明确：把验证过的能力固化为模块，让下一次编辑少一些重复试探，多一些可复用的步骤。
