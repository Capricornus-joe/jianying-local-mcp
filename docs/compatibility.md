# 兼容性与验证范围

Jianying Local MCP 是第三方本地草稿生成器，不是剪映官方 API。它生成可交给 Mac 剪映专业版打开的草稿，并提供本地媒体处理与管理计划编辑工具。应用的私有草稿格式会变化，兼容性仍属实验性。

## 运行依赖

| 项目 | 要求 |
|---|---|
| Python | 3.11 或更新版本 |
| MCP Python SDK | `mcp>=1.28,<2` |
| FFmpeg 提供器 | `imageio-ffmpeg>=0.6,<0.7`；也可用 `JIANYING_FFMPEG` 指向本地可执行文件 |
| 测试依赖 | `pytest>=8,<10`，通过项目的 `test` extra 安装 |
| MCP 传输 | stdio；客户端需自行配置服务的启动命令 |
| 原生应用目标 | macOS 上的剪映专业版；已有历史样片在应用版本 11.4.0 验证 |

这里的 **11.4.0 是剪映专业版的版本号，不是 macOS 版本号**。Python 依赖能够安装，并不意味着相应系统上的剪映或 CapCut 已获验证。Windows 剪映、CapCut 国际版和其他 Mac 应用版本没有通用兼容保证。

## 已验证到哪一步

| 验证层次 | 已有记录 | 不能由此推断 |
|---|---|---|
| 计划与草稿结构 | 参数、时间范围、素材引用、文字编码、修订、发布回滚等自动测试 | 所有字段会被每个剪映版本正确渲染 |
| MCP 协议 | 真实 stdio 子进程完成初始化、工具发现和调用；0.3 批处理与分页实测 | 客户端已经自动安装服务，或原生应用已经打开工程 |
| 原生可编辑性 | 0.1 的 6 秒历史样片可在应用中打开、修改中文字幕并导出 | 任意已有草稿均可回读并继续修改 |
| 原生效果 | 0.2 的 16 秒历史样片在 Mac 剪映专业版 11.4.0 打开并由 GUI 导出 | 每个特效、字体、账号、素材编码及参数组合都通过 |
| 0.3 新行为 | 程序回归与三轮真实 stdio 基准验证批处理、紧凑响应和缓存相关行为 | 0.3 已另做一次覆盖新增接口的完整原生导出验收 |

0.1 的应用版本记录在验证过程中有变化，最后复查为 11.4.0；它不应被计作多个应用版本各自独立的兼容测试。0.2 的原生样片为 16 秒、480 帧，导出文件为 1920×1080、30 fps、H.264 与 AAC。样片中的具体效果包括线性缩放/旋转、视频和文字渐显、裁剪/镜像、画中画、圆形与圆角矩形蒙版、缓存叠化、图片不透明度变化，以及部分文字样式和音频淡入淡出。

线性蒙版、所有九种运动预设、完整文字样式组合和任意缓存效果没有逐项原生验收。透明度关键帧在历史样片中有效，其他片段类型、应用版本或组合仍需核对实际导出。长时间线和复杂多层动画的重复导出稳定性也没有普遍保证。

0.3.0 的记录为 **375 项测试、60 个子测试通过**，另有真实 stdio 基准。测试数量与样片数量分开统计；程序测试不替代人工查看画面、声音与可编辑对象。参见[性能与测试方法](performance.md)和[测试源码](../tests)。

## 工程与文件边界

- `create_draft` 生成管理工程；`publish_draft` 才向剪映首页登记一个新的原生工程。发布前必须完全退出剪映，并保持退出直到发布结束。
- 每次修订都使用新的工程名。源管理工程不被覆盖；批处理把多步修改合并为一个新修订，不是原位编辑。
- 只有本工具创建的管理计划可继续编辑。`read_native_draft` 可以检查可识别的明文草稿，但它不是通用导入器。
- **不支持加密草稿回读、解密或修改。** 在剪映 GUI 中进行的修改不会同步回 MCP 管理计划；再次从管理计划生成时不会自动包含这些 GUI 修改。
- 草稿会复制媒体到自己的 `Resources/`。原生动画和转场仍引用本机已下载的效果缓存，不能据此保证跨机器携带资源后仍能播放。
- `process_media` 将调色、倒放和音频处理写入新媒体文件；这些处理不是剪映里可逐项开关的调整参数。普通字幕和 `text` 片段则生成原生文字对象。

## 当前明确限制

**没有 Mac 原生自动导出工具。** 发布不会启动剪映、操作时间线或输出成片；历史原生导出均由桌面界面操作完成。也没有提供 GUI 双向同步、复杂组合片段的通用往返编辑、语音识别、自动配音、曲线变速、智能抠图或会员资源解锁。

素材必须是受支持的本地文件；不接受网络媒体 URL 或播放列表。直接创建草稿时拒绝带非零旋转元数据的视频。应先生成方向正确的新文件并检查画面，再用于草稿。

时间以秒输入、以整数微秒写入草稿，但实际取帧仍受源帧率、工程帧率和原生渲染器影响。微秒字段不等于原生解码能实现微秒级取帧。字号换算、颜色、透明混合、裁切和关键帧都应在目标应用的真实导出中核验。

新建工程返回 `native_app_verified=false` 是有意设计：生成器不能自行证明这一个工程已经被原生应用正确打开与导出。

## 新环境的最小验证

1. 使用自己的短视频、静态图片、音频与原生文字生成一个小工程，先验证媒体和计划参数。
2. 完全退出剪映，预检发布目标后登记新工程。
3. 在剪映打开，检查轨道与资源，修改一句字幕以确认它仍是文字对象。
4. 由剪映导出，核对画面、声音、时长、字幕及所需效果；复杂效果至少再检查一次重复导出。

保存应用版本和实际导出测量结果。只有确认过的功能与版本可以作为后续工程的兼容性依据。
