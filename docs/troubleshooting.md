# 安装与使用排查

## 启动后没有提示，是否卡住？

`bash run.sh` 启动的是 stdio MCP 服务，它会等待客户端消息。先运行 `bash run.sh doctor` 查看环境；不要在协议输出中额外打印调试日志。

## 客户端启动失败

先执行 `bash setup.sh`，再按根目录 `mcp-client.example.json` 将 `command` 设为本机 `.venv/bin/python` 的绝对路径，`args` 保持 `["-m", "jianying_local_mcp", "serve"]`。迁移仓库后重新创建虚拟环境并更新路径。要换 Python，请直接修改 `command`；`JIANYING_MCP_PYTHON` 只对 `bash run.sh` 包装入口生效。

依赖明确限制 `mcp>=1.28,<2`。不要直接把SDK v2的示例接口套用到这个版本。

## 创建后在剪映首页找不到工程

`create_draft` 只生成 MCP 管理目录中的自包含工程。需要在退出剪映后使用 `publish_draft` 发布到真实原生草稿根目录。发布仅新建原生项目，不会启动应用或导出视频。确认 `draft_root` 中有可识别的首页索引。

## 旧脚本找不到返回结果里的 plan

v0.3 默认简要返回。编辑工具传 `include_plan=true` 获取完整计划；已保存工程用 `read_managed_project` 的 `view=full`。需要片段ID时使用 `view=clips`，支持 `offset`、`limit` 和 `track`。

预检结果不会写盘，因此不能用读取工程工具取回未保存的预览。重新调用该预检并加 `include_plan=true`。

## 素材变更后会读到缓存旧数据吗？

缓存每次检查规范路径、文件身份、大小、纳秒时间、模式与FFmpeg身份；变化后重新读取。缓存仅在进程内、最多2048项、最长5分钟，失败不会被缓存。素材在读取期间变化会被拒绝，请文件稳定后重试。

## 动画、转场或蒙版无法使用

先看 [兼容性与验证范围](compatibility.md)。本机缓存存在不等于当前账号有使用权限，也不等于所有版本都能成功导出。资源工具只解析已审阅的小型目录，不下载会员效果。剪裁、重排尽量先于关键帧、淡入淡出和转场，避免改变它们的时间语义。

## 为什么加密草稿不能修改？

工具只读取明文原生草稿并修改自己的管理计划，不解密任意原生工程。剪映GUI修改不会自动同步回管理计划。请保留原工程，使用新版本进行工具编辑。

## 提交问题需要什么？

提供系统与剪映版本、Python/MCP版本、工具名、最小合成例子和精简错误信息；不要附带账户令牌、本机完整日志、私人素材或整个项目。详见 [贡献指南](../CONTRIBUTING.md)。
